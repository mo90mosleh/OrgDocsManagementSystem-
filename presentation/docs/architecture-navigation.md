# Architecture exploration and organization filters

The architecture route now starts from actual root nodes and shows one immediate child level at a time. Group cards drill into their children; the clickable ancestry trail, parent button and overview action provide explicit navigation. The overview returns to actual roots, without inventing classifications or flattening the hierarchy. Cards retain real codes, computed depths, source classifications and draft/reference labels.

Global search covers all group/process names and codes, normalizes Persian/Arabic keyboard variants and spacing, and shows each result's full ancestry. Selecting a result reveals its branch. Process cards open a summary without leaving architecture; a separate profile link opens the full process page. Summary content uses the recorded objective/summary, owner unit, actual process/KPI links and actual horizontal process relations. Missing content stays empty. Groups without children and searches with no matches have truthful empty states.

Branch ID, selected process ID, search text and scroll position are stored as same-tab view preferences scoped to organization/role. Opening a profile/KPI and using global Back, or refreshing, restores that architecture context. No business content is written into browser persistence. The existing portal authentication, chart navigation and dataset remain unchanged.

Process and KPI catalogs now share department and grouped-role filters. Selecting a role sets its recorded department; the interface explicitly explains that role filtering operates through that department. Processes filter by `owner_org_unit_id`; KPIs filter by stored `process_kpis` associations with those processes, deduplicated by KPI identity. No direct role ownership or KPI department ownership is invented. Organization filters compose with existing text/readiness filters, can be cleared, and survive detail navigation/Back within the same tab. Empty departments show zero results; unlinked KPIs remain visible when organization filtering is cleared. These are read-only view changes with no schema/business-data writes.

Tours cover the staged navigation, ancestry, search, preview and both catalog filters. Automated tests cover real ancestor chains, descendant counts, keyboard normalization, drilling/breadcrumbs, global search/empty results, separate preview/profile actions, mobile bounds, branch/search/selection/scroll restoration, exact department/role-derived process/KPI results, reset/empty filters and readiness/text composition. Desktop/mobile screenshots were inspected.

Validation completed: TypeScript/build, 24 unit/security/navigation tests and 23 relevant browser scenarios across targeted runs passed. Coverage includes existing tours, feedback privacy/persistence, authentication/profile/video behavior, architecture navigation/restore and both organization filters. No production test records were created.
